# Roast Panel — Meet Live Concierge
**Date:** 2026-05-11
**Round:** 11 (follow-up roast)
**Project:** Real-time AI Assistant with Architectural Diagramming for Google Meet
**Audience:** Team / Stakeholders

## Persona 1 — The Paranoid Security Researcher

You've added token validation in `app/auth.py`, which is a step up from "trust everyone," but your perimeter is still like a screen door on a submarine.

- **WebSocket is still a "Black Box"**: While you validate tokens for API calls, the `/ws` endpoint in `main.py` accepts a `meeting_id` query param and then launches `live_session`. If I hit that WebSocket directly without the `init` message, I can still tie up a handler and a Gemini session. You should validate the token *during* the handshake or immediately upon connection before spawning the Gemini task.
- **The CSP is still excessively permissive**: `response.headers["Content-Security-Policy"] = "default-src * 'unsafe-inline' 'unsafe-eval'; ..."` in `main.py` is an open invitation. "Restored permissive CSP" from your git history (per the comment on line 55) is not a fix; it's a surrender. You're framing high-value Google Docs—don't let an XSS vulnerability turn this into a data exfiltration tool.
- **`allow-unauthenticated` in Cloud Run**: Your deploy command in `STATUS.md` uses `--allow-unauthenticated`. Even with token validation on individual requests, you're exposing your entire attack surface (FastAPI, WebSocket handlers) to the open web. Use an `IAM` invoker and handle the OIDC handshake if possible, or at least put a strict API key on the WebSocket.
- **Token Leakage in Logs**: `print(f"[ws] init {workspace_user[0]}", flush=True)` in `main.py` is fine, but make absolutely sure `session_token[0]` never finds its way into a `print` or an error traceback that ends up in Cloud Logging.

**Gaps:**
| Severity | Problem | Fix direction |
|---|---|---|
| Critical | Wide-open CSP | Whitelist Google domains specifically; remove `unsafe-eval`. |
| Significant | Unauthenticated WS handshake | Require a valid OAuth token or API key *before* accepting the WebSocket connection. |
| Significant | `allow-unauthenticated` | Restrict Cloud Run to authorized invokers or add a robust pre-middleware auth check. |
| Minor | Potential token logging | Ensure structured logging explicitly excludes token fields from all output. |

## Persona 2 — The Impatient UX Designer

You've got "Elite" layout switchers, but your "Connect" experience is a multi-step obstacle course.

- **The "Popup" Fatigue**: I have to click "Sign in with Google", handle a popup, then click "Connect to Meeting". Why isn't this a single "Get Started" flow? If the add-on is already running in a signed-in Meet session, you should be attempting to grab a token silently first.
- **Build-Time Env Traps**: `index.tsx` line 8 still checks `CLOUD_PROJECT_NUMBER` at build time. If I deploy with the wrong `.env.production`, the add-on is bricked until a full redeploy. This config should be fetched from the backend `/api/config` on init.
- **Hidden Audio element complexity**: Your README note about `<audio muted>` is a technical badge of honor, but for a user, it's a "why is it silent?" bug waiting to happen. The UI should have a "Sound Check" indicator to confirm the Opus decoder is actually working.
- **Diagram "Flicker"**: Even with "Flicker-free PNG rendering," the jump from "Generating..." to a new PNG creates a cognitive load. A simple transition or progress bar *inside* the diagram panel would make it feel "live" rather than "periodically updated."

**Gaps:**
| Severity | Problem | Fix direction |
|---|---|---|
| Significant | High friction "Connect" flow | Implement a single-click "Join & Auth" button. |
| Significant | Build-time env dependency | Move `CLIENT_ID` and project numbers to a runtime API endpoint. |
| Minor | Lack of audio health signal | Add a small "Audio Decoded" indicator in the status bar. |
| Minor | Discrete diagram updates | Use a CSS fade-in or loading overlay for PNG refreshes. |

## Persona 3 — The Skeptical Credibility Critic

Okay, I see the diagramming logic now—it's real. But it's also incredibly fragile.

- **The LLM "Hallucination" Gap**: `app/diagrams.py` uses an LLM to generate D2 code. If the meeting transcript is messy (which it is), the LLM will generate invalid D2. Your "Simple fallback" on line 64 is just a "User -> System: Architecting..." node. That's a 100% loss of value when it fails. You need a "Correction" loop where the LLM sees the D2 error and tries to fix the code.
- **Context Limit Truncation**: Line 76 of `app/diagrams.py` truncates the transcript at 6,000 characters. For a 60-minute meeting, you're throwing away the first 45 minutes of context. You need a rolling summary or a better way to extract the "architectural meat" from the transcript.
- **The "Master Architect" Claim**: Your `STATUS.md` claims "Zero Technical Clutter." But if Gemini decides to include a technical note, your `re.sub` logic on line 11 might miss it. Don't rely on regex to "clean" LLM output; use a strict system prompt and validation schema.
- **Latency in "Live"**: 100ms batches + WebSocket + Vertex AI latency means the diagram is always 5-10 seconds behind the conversation. Calling it "Real-time" is a stretch. It's "Near-real-time asynchronous diagramming."

**Gaps:**
| Severity | Problem | Fix direction |
|---|---|---|
| Significant | Fragile D2 generation | Implement an auto-correction loop for invalid D2 code. |
| Significant | Context truncation | Replace simple truncation with a rolling summary or RAG-based context extraction. |
| Minor | Latency expectations | Document the 5-10s "thinking" delay in the UI so users don't think it's broken. |

## Persona 4 — The Grumpy Maintainer

You've built a complex multi-process system with zero observability and a monolithic frontend.

- **Observability is non-existent**: You're still using `print(..., flush=True)` everywhere. When `librsvg2-bin` fails on Cloud Run, you'll see a generic "render exception" (line 72) in a sea of unformatted text. You need `google-cloud-logging` with trace IDs to link WebSocket messages to backend errors.
- **The "index.tsx" Beast**: It's a 70,000-byte file (per `ls`). That is a maintenance nightmare. If I want to change the diagram style buttons, I have to navigate a forest of WebSocket logic and AudioWorklet setup. Break this into `AudioService`, `DiagramPanel`, and `TranscriptView`.
- **Subprocess Vulnerability**: `app/diagrams.py` line 52 calls `asyncio.create_subprocess_exec("d2", ...)`. If `d2` hangs or hangs on a specific input, you could leak processes until the Cloud Run instance OOMs. You need a strict timeout on that subprocess.
- **Hardcoded Engine IDs**: line 33 of `main.py` has `2432159852814925824` hardcoded. If the reasoning engine is redeployed, the code is broken. This must be an environment variable.

**Gaps:**
| Severity | Problem | Fix direction |
|---|---|---|
| Significant | Monolithic frontend | Decompose `index.tsx` into domain-specific components. |
| Significant | Process management | Add `timeout` to `asyncio.subprocess` calls to prevent zombie processes. |
| Significant | Hardcoded Engine IDs | Move `WORKSPACE_AGENT_ENGINE` and project IDs strictly to `.env`. |
| Minor | Missing structured logging | Implement a standard Python logger with Cloud Logging integration. |

## Panel Verdict

**Gaps by severity (cross-panel):**
| Severity | Gap | Persona(s) | Fix direction |
|---|---|---|---|
| **Critical** | Wide-open CSP | Security | Whitelist domains; remove `unsafe-eval`. |
| **Significant** | WebSocket/Handshake Auth | Security | Validate tokens *before* launching the Gemini session. |
| **Significant** | Fragile D2/Context logic | Critic | Add D2 error correction and rolling transcript summaries. |
| **Significant** | Code Smells & Process Risks | Maintainer | Modularize `index.tsx`; add timeouts to subprocesses. |

**Exit criteria:**
- [ ] CSP restricted to `https://*.google.com`.
- [ ] WebSocket handshake validates the `Authorization` header/token.
- [ ] D2 generation includes a retry-on-failure loop.
- [ ] `index.tsx` split into at least 3 files.

**Recommended fix order:**
1. **Security**: Tighten CSP and WS auth first. These are the biggest "real world" risks.
2. **Reliability**: Fix the D2 failure path and context truncation.
3. **Refactor**: Split `index.tsx` and move hardcoded IDs to env vars for maintainability.
4. **UX**: Smooth out the "Connect" flow.
