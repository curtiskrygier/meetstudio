# meet-live-concierge — Component Reference

This add-on implements a voice-activated workspace assistant for Google Meet.

## Core Patterns

### 1. Multi-Project Architecture
- **Identity Project**: `649226456677` — Contains the Marketplace SDK registration and OAuth Consent.
- **Hosting Project**: `649226456677` — Contains the Cloud Run service and GCS sources.
- **Handshake**: `index.tsx` must use the *Identity* number for `createAddonSession`.

### 2. Audio Pipeline
- **Opus Decoder**: Chrome's decoder is lazy. We use a hidden `<audio muted>` element for every track to force decoding so `AudioWorklet` receives non-silent PCM.
- **Batching**: PCM chunks are batched into 100ms segments (1600 samples) before being sent to Gemini Live to prevent RPM quota breaches.

### 3. Workspace Agent Integration
- **Reasoning Engine**: The backend calls a delegated Vertex AI Reasoning Engine (GE04) to handle Workspace tasks (docs, drive, search).
- **Redirection**: Documents generated by the agent are automatically "pushed" to the Meet main stage via `sidePanelClient.startActivity`.

## Save to Drive Functionality

### Implementation Details
- **Scope**: Uses `https://www.googleapis.com/auth/drive.file`.
- **Folder Management**: `get_or_create_meeting_folder()` checks for a "Meet Recordings" folder in `root`. If not found (or not created by this app), it creates a new one.
- **Shortcut Logic**: `save_doc_shortcut_to_drive()` creates an `application/vnd.google-apps.shortcut` pointing to the generated document ID.

### Troubleshooting Avenues (Why it might be broken)
1. **Scope Conflict (Blindness)**: `drive.file` only sees files created by the current Client ID. If a user has an existing "Meet Recordings" folder created by a different version of the bot, the current bot will be "blind" to it, fail the search, and potentially error out on a duplicate creation attempt if naming collisions occur at the API level.
2. **Shared Drive Blockers**: Standard Drive API calls often fail in Shared Drives unless `supportsAllDrives=True` is explicitly passed in the query parameters.
3. **Identity Handshake**: The `access_token` must be present in the `session_token[0]` list in `main.py`. If the `init` message fails or the token is null, all Drive operations will silently skip or fail with `401`.
4. **Target ID Validation**: If the generated URL doesn't match the regex `/d/([a-zA-Z0-9_-]+)`, the shortcut creation will skip.

### Proposed Fixes to Explore
- **Elevate Scope**: Change to `https://www.googleapis.com/auth/drive` to confirm if scope restriction is the cause.
- **Force Metadata**: Add `supportsAllDrives=True` to all Drive API calls in `main.py`.
- **Backend Logging**: Add verbose logging to `get_or_create_meeting_folder` to see the exact HTTP response from Google.
