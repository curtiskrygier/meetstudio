# Roast Panel — Meet Live Concierge
**Date:** 2026-05-11
**Round:** 2 (follow-up roast)
**Project:** Real-time AI Assistant with Architectural Diagramming for Google Meet
**Audience:** Team / Stakeholders

## Persona 1 — The Paranoid Security Researcher

You've patched the obvious holes, but you're still leaving the back door unlocked.

- **Handshake Auth is "Token-Only"**: You're validating the token against Google's `tokeninfo`, which is good. But you're still using `--allow-unauthenticated` on Cloud Run. This means your entire FastAPI surface is exposed. An attacker doesn't need a token to hit your `/api/render` or `/api/session` endpoints with large payloads to see what happens.
- **D2 Injection Potential**: In `app/diagrams.py`, you're cleaning D2 code with regex, but then you're writing it to a file and running it via `subprocess.exec`. If Gemini is tricked into outputting something that bypasses your regex, you're one "D2 feature" away from a local file read or worse. You should be using a strict schema or a D2-specific parser before writing to disk.
- **Token in URL Parameters**: To get the token to the Stage, you're appending it as a query param in `index.tsx`. URL parameters are logged by proxies, browsers, and servers. If a user shares their meeting URL (which now has their token), they've shared their session. You should be using `window.postMessage` or a temporary short-lived "Stage Ticket" from the backend instead of passing the raw OAuth token in the URL.
- **No Rate Limiting**: You've added handshake auth, but once I'm in, I can flood your WebSocket or `/api/diagram` endpoint. One valid user can still bankrupt your Vertex AI budget in ten minutes.

**Gaps:**
| Severity | Problem | Fix direction |
|---|---|---|
| Significant | Token in URL params | Move token passing to `postMessage` or use a backend-generated session ticket. |
| Significant | Unprotected API endpoints | Remove `--allow-unauthenticated` and use OIDC/IAM or add the token check to all `@app.post` routes. |
| Minor | D2 Injection risk | Replace regex cleaning with a more robust D2 syntax validator. |

## Persona 2 — The Impatient UX Designer

The refactor made the code prettier, but the user experience is still a bit "beta".

- **The "Update" Button Paradox**: You've added a manual "Update" button for diagrams, but you still have a `diagramInterval` firing every second. Why? If I'm manually typing context, the auto-update might overwrite my changes or fight me. Choose a mode: Auto or Manual.
- **Audio "Play" Gesture**: You're calling `audioService.initialize()` on connect. If that's not tied to a direct `click` event (e.g., if you auto-connect after OAuth), the browser will block audio playback. You need a big, unmistakable "Start Audio" button.
- **Checklist UX**: Your connecting checklist shows "Joining meeting audio" as the last step. If the Meet Media API fails (which is common), the UI just hangs there. You need a "Troubleshoot" link or a clear "Retry" state.
- **Flicker-free is still PNG**: You're fetching a PNG from a URL. Even if it's cached, there's a network round-trip. Why not stream the SVG directly over the WebSocket for instant rendering?

**Gaps:**
| Severity | Problem | Fix direction |
|---|---|---|
| Significant | Conflicting update modes | Disable `diagramInterval` if `diagramContext` has pending changes or is focused. |
| Significant | Audio Playback blocking | Ensure `audioService.initialize` is only called within a explicit user `click` handler. |
| Minor | Hanging checklist | Add a timeout and "Troubleshoot" button to the connection checklist. |

## Persona 3 — The Skeptical Credibility Critic

You fixed the "Architect" branding, but now you've introduced "AI Hallucination Loop 2.0".

- **The Auto-Correction Loop is a Band-Aid**: If the LLM generates invalid D2 once, there's a high probability it will generate it again during the "correction" phase because it doesn't actually understand the D2 syntax—it's just guessing based on its training data. You're doubling your Vertex AI costs for a feature that might still fail.
- **"Near-real-time" is still slow**: A 15-second timeout on D2 compilation? If a diagram takes 14 seconds to compile, the user is already talking about the next slide. Your "Concierge" is always three steps behind the guest.
- **Workspace Tooling limitations**: Your `workspace_agent` tool is still a black box in `main.py`. If it fails to find a document, the agent just says "I couldn't find it." The user has no visibility into *why*—is the token expired? Are permissions missing?

**Gaps:**
| Severity | Problem | Fix direction |
|---|---|---|
| Significant | AI Cost/Reliability trade-off | Monitor the failure rate of the "Correction" loop; consider a simpler D2 generation prompt. |
| Minor | Tool transparency | Return more granular error states from `workspace_agent` (e.g. "Permission Denied" vs "No Results"). |

## Persona 4 — The Grumpy Maintainer

The refactor is a great start, but you've just moved the mess from one file to five.

- **Import Spaghetti**: You have `import { mainStyles } from './internal/styles'` and `import './internal/components/gdm_status_view'`. Why are components side-effect imports while styles are named? Pick a pattern.
- **Service Singletons?**: `this.audioService = new AudioService()`. If `GdmArchitectAgent` is re-mounted (which can happen in some Lit/Meet edge cases), you're leaking AudioContexts. These services should be singletons or properly managed via a lifecycle.
- **Error Propagation**: `handleWebSocketMessage` catches errors and... does nothing. `try { ... } catch { }`. If a message fails to parse, the app just dies silently. Log the error, increment a counter, show a toast—anything but a silent catch.
- **Subprocess Shelling**: You're still calling `rsvg-convert` and `d2` via shell. If these binaries aren't in the container PATH, the app crashes. You should have a `healthcheck` or a `pre-run` script that verifies all binary dependencies.

**Gaps:**
| Severity | Problem | Fix direction |
|---|---|---|
| Significant | Service Lifecycle leaks | Implement a proper `Service Registry` or ensure `disconnect()` fully clears service state. |
| Significant | Silent Catch blocks | Replace empty `catch { }` with at least a `logger.error` call. |
| Minor | Binary dependency risk | Add a startup check in `main.py` to verify `d2` and `rsvg-convert` are executable. |
