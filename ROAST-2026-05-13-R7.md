# Roast Panel — Meet Live Concierge
**Date:** 2026-05-13
**Round:** 7 (follow-up roast)
**Project:** Real-time AI Assistant with Architectural Diagramming for Google Meet (A2UI architecture)
**Audience:** Team / Internal

## Persona 1 — The Paranoid Security Researcher

You've built a "Ticket" system for auth, but your implementation is a masterclass in "Security by Obscurity."

- **The "Token Leak" is still there**: `main.py` line 269: `ticket_data = auth_tickets.pop(token, None)`. You're still calling the query parameter `token` in the side panel's WebSocket URL. If a proxy logs this, they have the ticket. While tickets are short-lived, you're just passing the risk around instead of using a proper secure handshake (like OIDC or encrypted state).
- **The "bleach" bypass**: You're using `bleach.clean` in `main.py`, but your `ALLOWED_ATTRS` for `div` includes `id`. An attacker could inject a div with an ID that conflicts with your UI elements (like `diagram-container`), potentially hijacking your DOM manipulation or breaking the app's internal logic via CSS injection.
- **WebSocket is still unauthenticated after handshake**: Once the WS is open, you trust everything coming from the "browser." If an attacker gains XSS in your side panel, they can spoof `type: toggle_audio` or `type: view_change` directly to the backend. You have no per-message signature or session validation.
- **Dependency Pinning**: Your `requirements.txt` is likely unpinned or loosely pinned. One bad release of `fastapi` or `google-genai` and your production security posture changes without a single line of code changing in your repo.

**Gaps:**
| Severity | Problem | Fix direction |
|---|---|---|
| Significant | ID Injection in `sanitize_html` | Remove `id` from `ALLOWED_ATTRS` in `main.py`. |
| Significant | Unpinned dependencies | Pin all versions in `requirements.txt` using `==`. |
| Minor | Token/Ticket naming confusion | Rename the query param to `ticket` in the Side Panel code to match the backend logic. |

## Persona 2 — The Impatient UX Designer

I see you added a "Command Bar" to the stage. It's a nice touch, but it feels like a ghost ship.

- **The "Updating..." black hole**: When I click "Update" on the stage, the button says "Updating..." for 2 seconds (hardcoded in `main_stage.html`). But if the backend takes 10 seconds to generate the diagram, the button reverts to "Update" while the diagram is still stale. The stage has no idea if the side panel actually finished the job.
- **The "New" diagram feedback**: Clicking "New" in the side panel or stage wipes the diagram. But there's no "Are you sure?" prompt. If I accidentally click it during a complex discussion, my progress is gone instantly.
- **Transcription "Label" confusion**: You added a `label` field in `main.py` (line 351). But if Gemini is speaking, the label is "Gemini Architect". If I'm speaking, it's "You". Why is this inconsistent with the Side Panel's "User" role? Stick to one naming convention across the whole app.
- **Mobile? Forget it**: Your 16:9 cinematic ratio looks great on a 27" monitor, but if I open this on a tablet or a laptop with a sidebar open, your `max-width: calc((100vh - 200px) * (16 / 9))` logic might overflow or under-scale. You need media queries, not just a magic math string.

**Gaps:**
| Severity | Problem | Fix direction |
|---|---|---|
| Significant | Stale Stage Feedback | Implement a "Generation Started/Finished" event that the stage can listen for. |
| Minor | Destructive "New" button | Add a simple confirmation dialog for the "New" diagram action. |
| Minor | Inconsistent Role Labels | Standardize on "Gemini Architect" and "User" in both backend and frontend. |

## Persona 3 — The Skeptical Credibility Critic

A2UI is a great buzzword, but your "Dumb Renderer" is actually a "High-Latency Puppet."

- **The "Hybrid" Mess**: You claim to have a Server-Driven UI, but your `index.tsx` still has 900 lines of code. It's still managing the Meet SDK, the AudioService, the WebSocket lifecycle, AND it's doing manual rendering for the Transcript and the Diagram section (lines 803-847). You haven't migrated; you've just added a new layer of complexity.
- **Vertex AI "Cost Loop"**: Your `update_interface` tool allows the agent to update the `status_text`. If the agent enters a loop or is too "chatty," you're making a round-trip to the server just to update a line of text. This should be handled by a lower-overhead status channel, not the full A2UI state broadcast.
- **Manual "Update" vs Auto-Gen**: You've disabled auto-gen if `diagramContext` is present (line 527 of `index.tsx`). This means if a user types one character into that box and forgets about it, the "Live" diagrammer is now permanently bricked until they manually click "Update." That's a UX disaster disguised as a "feature."

**Gaps:**
| Severity | Problem | Fix direction |
|---|---|---|
| Significant | Partial A2UI Migration | Move the Transcript and Diagram sections into the server-driven component tree. |
| Significant | Bricked Auto-Gen | Automatically resume auto-gen if the context box hasn't been touched for N seconds. |
| Minor | Over-engineered status | Use a dedicated WebSocket message type for transient status updates to reduce payload size. |

## Persona 4 — The Grumpy Maintainer

You've modularized the frontend, but you've left the backend to rot in a single 500-line file.

- **`main.py` is the new monolith**: You've got API routes, WebSocket handlers, tool definitions, HTML sanitization, and state management all in one file. If I want to change how `workspace_agent` works, I have to navigate around your A2UI broadcast logic. Split this into `api/`, `ws/`, and `agent/`.
- **`auth_tickets` memory leak**: Your ticket cleanup task (line 74) runs every 5 minutes. But you're using a plain `dict`. If 10,000 people use this and close their browser before the ticket is consumed, that dict will grow until it OOMs. Use a TTL-based cache or a proper Redis/Firestore store for production.
- **Z-Index Wars**: You've hardcoded `z-index: 300` for the command bar and `200` for the transcript. When Meet adds a new floating control or a doc preview overlaps, your UI is going to flicker or disappear. You need a centralized layer management system.
- **Traceback Printing**: `traceback.print_exc()` on line 386 is fine for dev, but it's sloppy for production. It goes to stderr and doesn't get captured as "Error" level in many log aggregators. Use `logger.exception("WebSocket failure")`.

**Gaps:**
| Severity | Problem | Fix direction |
|---|---|---|
| Significant | Monolithic Backend | Refactor `main.py` into a modular package structure. |
| Significant | In-memory Ticket Risk | Replace the `auth_tickets` dict with a thread-safe TTL cache. |
| Minor | Debugging cruft | Replace `traceback.print_exc()` with `logger.exception()`. |
