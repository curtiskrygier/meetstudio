## Persona 1 — The Paranoid Security Researcher

You've finally locked the front door, but you left the "Fetch" window open.

- **SSRF in `fetch_url`**: I warned you about this in R8. `app/utils.py` still uses a naive `httpx.get` on any URL Gemini provides. An attacker can still trick the agent into fetching `http://169.254.169.254/computeMetadata/v1/instance/service-accounts/default/identity` to exfiltrate the server's identity token. You need a domain allowlist or a private IP blocklist.
- **`shutil.copytree` in Temp Dirs**: In `app/diagrams.py`, you're copying the `assets/icons` folder into a world-writable `/tmp` directory. While short-lived, you're spreading your static assets into a less controlled execution space. Use absolute paths to the original assets instead of copying them into temp space for every render.
- **WebSocket Handshake "Ticket" reuse**: You're `pop()`ing the ticket from `auth_tickets` on handshake. Good. But if the connection drops and the frontend tries to auto-reconnect, the ticket is gone and the user is hard-locked out until they refresh the whole page. You need a "Session Token" issued *after* the ticket is consumed.

**Gaps:**
| Severity | Problem | Fix direction |
|---|---|---|
| Significant | SSRF vulnerability in `fetch_url` | Add a regex/check to `app/utils.py` to block private/metadata IPs |
| Significant | Reconnection lockout | Implement a long-lived session cookie or token after ticket consumption |
| Minor | Inefficient asset copying | Reference icons via absolute `/app/assets/...` paths in D2 instead of copying |

## Persona 2 — The Impatient UX Designer

The Side Panel prompt is great, but the feedback loop is "Silent but Deadly."

- **The "Apply" button is a ghost**: When I click "Apply" in the new Side Panel prompt bar, the UI sends a POST to `/api/ui-prompt`. The backend parses it, mutates state, and broadcasts. But the frontend doesn't show any "Applied!" success state or a "Failed to parse" error message. I'm just typing into a void and hoping the UI shifts.
- **No Progress for UI Prompts**: Gemini Flash is fast, but it's not instant. The "..." on the button is a start, but if the broadcast takes 2 seconds, the button should stay in a loading state until the *new* state arrives via WebSocket.
- **Prompt Bar Placeholder is vague**: "Change the UI… e.g. go matrix, focus mode" is okay, but it doesn't tell me I can also say "Hide the transcript" or "Show a document about X." It needs a more expansive hint.

**Gaps:**
| Severity | Problem | Fix direction |
|---|---|---|
| Significant | Missing Prompt Feedback | Surface the `applied` result from `/api/ui-prompt` as a transient toast or status update |
| Minor | Optimistic Loading | Keep the "Apply" button disabled until the A2UI_STATE message confirms the shift |
| Minor | Vague UX Hints | Expand the placeholder text to list more available commands |

## Persona 3 — The Skeptical Credibility Critic

The A2UI Protocol is technically "factual" now, but the Registry is an empty mall.

- **The "Registry" is just a wrapper for the old switch**: You moved the logic to a `Map`, which is architecturally cleaner, but you still only have the same 5 components. If you want this to feel "Next Level," you need at least one truly dynamic component (like a Poll or an Agenda) that isn't just a basic view of meeting metadata.
- **Transcript is still the "Special Case"**: It's the only section that *doesn't* come from the `components` props (it uses `this.transcript` local state). This makes your A2UI claim 90% factual, but that 10% is where all the real-time activity happens.
- **D2 Formatting is "Better," not "Fixed"**: Your `fill: transparent` fix is a clever hack, but it means if I use a light theme (`corporate`), your "transparent" nodes might have low contrast against a white background if the stroke is still light blue. You need theme-aware D2 style generation.

**Gaps:**
| Severity | Problem | Fix direction |
|---|---|---|
| Significant | Empty Registry | Implement at least one "High Utility" component like `gdm-action-list` |
| Significant | Manual Transcript State | Move the transcript array into the server-provided `props` to be 100% A2UI |
| Minor | Theme-Diagram Mismatch | Pass the current theme colors into `render_d2` to adjust stroke/fill dynamically |

## Persona 4 — The Grumpy Maintainer

The modularization is 80% done, but `main.py` is still a minefield of local variables.

- **`session_ui_state` vs `active_sessions`**: You added `active_sessions` to `app/config.py` but you're still defining a local `ui_state` in `live_session` and then copying it. This is a recipe for state drift. The agent tools should point directly to the global store, not a local reference that might get out of sync.
- **Hardcoded Cloud Project Number**: `index.tsx:128` still has `cloudProjectNumber: '649226456677'`. This should be an environment variable injected at build time, just like `CLIENT_ID`. If you hand this code to another team, it's a hard-coded blocker.
- **No Logging on `/api/ui-prompt` failures**: When the regex/JSON extraction fails, you return `{"ok": False}` but you don't log *what* Gemini actually returned. This makes debugging "why didn't my prompt work" impossible without adding print statements.

**Gaps:**
| Severity | Problem | Fix direction |
|---|---|---|
| Significant | Hardcoded Project IDs | Use `process.env.CLOUD_PROJECT_NUMBER` in `index.tsx` |
| Significant | State Management Drift | Refactor tools to operate on `active_sessions[meeting_id]["ui_state"]` directly |
| Minor | Opaque API failures | Log the `raw_text` from Gemini on parse failure in `/api/ui-prompt` |
