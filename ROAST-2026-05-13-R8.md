## Persona 1 — The Paranoid Security Researcher

Two rounds in and I still have DOM injection and an authentication bypass. I'm not impressed.

- **The `id` attribute is still in `ALLOWED_ATTRS`** (`main.py:30`): `'div': ['class', 'id']`. An AI-generated doc displayed via `update_interface` can inject a `<div id="control_bar">` and silently shadow your server-driven component IDs. The Lit component renders whatever the backend sends — there's no client-side ID namespace guard.
- **`/api/diagram/{diagram_id}/save` has zero auth** (`main.py:632`): Every other API endpoint in this file takes `Depends(token_required)`. This one takes nothing. It accepts `access_token` from the request body and uses it directly in `save_diagram_to_drive`. Anyone who can construct a `POST /api/diagram/<uuid>/save` request — with any token they supply — can write to Drive via your backend as a proxy. The service is publicly accessible (`allUsers` invoker). This is not a theoretical concern.
- **Requirements are still unpinned** (`requirements.txt:2–8`): `fastapi`, `google-genai`, `httpx`, `bleach`, `markdown` — all floating. `bleach` in particular has had security-relevant patch releases. A `pip install` during build can silently pull a version that changes sanitization behavior. Lock them.
- **Ticket parameter named `token` on `/ws`** (`main.py:508–509`): The comment says "We use the 'token' param name for compatibility." Compatibility with what? The frontend you control. Rename it to `ticket` and update `index.tsx`. A proxy log showing `wss://…/ws?meeting_id=X&token=Y` looks like a raw bearer token leak to any security scanner that reads it.

**Gaps:**
| Severity | Problem | Fix direction |
|---|---|---|
| Critical | `id` in `ALLOWED_ATTRS` persists — AI content can shadow server-rendered component IDs | Remove `id` from `div` in `ALLOWED_ATTRS` at `main.py:30` |
| Critical | `/api/diagram/{id}/save` has no `Depends(token_required)` — public auth bypass | Add `_=Depends(token_required)` to `save_diagram` at `main.py:632` |
| Critical | All deps in `requirements.txt` are unpinned — silent security regressions on build | Pin every dep with `==` using `pip freeze` output |
| Significant | `token` query param holds a ticket — misleads log scanners and auditors | Rename to `ticket` in `main.py:508` and matching `index.tsx` call |

## Persona 2 — The Impatient UX Designer

Three things that will make a user think the app is broken, and they're all invisible.

- **`diagramMode` silently swallows every tool call** (`main.py:351–353`): When `diagramMode` is True, the loop responds `{"result": "ok"}` to ALL tool calls — `workspace_agent`, `fetch_url`, `present_on_main_stage`, `update_interface` — and skips them. If a user in diagram mode says "fetch that link and incorporate it," Gemini gets a success response for `fetch_url` but nothing was fetched. It will confidently summarise content it never saw. No error, no warning, no indication to the user that any tool was dropped.
- **`Cache-Control: no-store` is gone from `serve_index`** (`main.py:639`): The SKILL.md documents this as *essential* — "Without it, Meet caches the HTML and loads stale content-hashed JS bundles indefinitely." The current `serve_index` returns a plain `FileResponse` with no cache headers. After every deploy, some users will get the old bundle and silently run stale code. This was present before and was removed.
- **`extra_components` grows without bound in a session** (`main.py:416–417`): Every `update_interface` call with `doc_data` appends a new component to `ui_state["extra_components"]`. There's no cap, deduplication, or eviction. Each `broadcast_a2ui()` call serialises and sends the entire list. In a 90-minute session with an active agent, this list can grow to tens of entries and every state update carries the full payload.

**Gaps:**
| Severity | Problem | Fix direction |
|---|---|---|
| Significant | `diagramMode` swallows all non-diagram tool calls silently | Allowlist only diagram-specific tools when `diagramMode` is True; pass others through or return an informative result |
| Significant | `Cache-Control: no-store` missing from `serve_index` — post-deploy stale bundle regression | Restore `response.headers["Cache-Control"] = "no-store"` on `FileResponse` at `main.py:639` |
| Significant | `extra_components` list grows unboundedly across a 90-minute session | Cap at N entries or replace (not append) doc views by ID |

## Persona 3 — The Skeptical Credibility Critic

The A2UI concept is solid. The execution still has a foot in two worlds.

- **`index.tsx` is 904 lines and the transcript is explicitly not server-driven** (line 272 comment: "Frontend currently manages the transcript array locally for performance"): That's a fine trade-off, but it means the core A2UI claim — "the backend drives the UI" — is only half true. The most visible, real-time element (the transcript) is still client-managed state. Don't call it A2UI and then leave the transcript out.
- **The `diagramContext` auto-gen gate at `index.tsx:526`** is a trap: `if (!this.diagramContext.trim()) { this.generateDiagram(); }`. One character typed into the refinement box disables auto-generation permanently until the box is cleared. There's no timeout, no "resume" button, no indication to the user that auto-gen has stopped. This has been open since R7 and the logic hasn't changed.
- **The SKILL.md describes the `fetch_url` tool as capping at 6k chars** but says nothing about domain restrictions. The tool is available in diagram mode and in normal mode, both. An adversarial meeting participant who can influence what the AI says can direct `fetch_url` at internal URLs. The GCP metadata endpoint (`http://169.254.169.254`) requires a specific header that a naive `httpx.get` won't send — but other internal Cloud Run services in the same VPC don't require that header.

**Gaps:**
| Severity | Problem | Fix direction |
|---|---|---|
| Critical | `diagramContext` permanently disables auto-gen with no recovery path — persists from R7 | Add an inactivity timeout (e.g. 30s) to resume auto-gen after the context box is last edited |
| Significant | Transcript is explicitly client-managed, undercutting the A2UI claim | Either move transcript into `components` array (accepting the perf cost) or document it as a known exception |
| Minor | `fetch_url` has no domain allowlist documented or enforced | Add a check in `app/utils.py` that rejects private IP ranges and metadata server addresses |

## Persona 4 — The Grumpy Maintainer

Three things I will curse you for in six months.

- **`/api/diagram/{id}/save` takes `access_token` from the request body** (`main.py:635`): Not only is it unauthenticated (see Security), the token-in-body pattern is a maintenance antipattern. Every other endpoint in this file uses `Depends(token_required)` — an established, consistent pattern. This one silently diverges. The next developer adding an endpoint will read the codebase, see 11 endpoints using the dependency pattern and one not, and either assume it's intentional or copy the wrong one. Add a comment at minimum; add auth at maximum.
- **`main.py` is 646 lines and the WebSocket handler is still inline**: The modular imports from `app/` are good progress, but `live_session` — the most complex function in the file — is still a 340-line monolith inside `main.py`. The A2UI broadcast logic, tool dispatch, transcript relay, and session state are all tangled together. When the workspace agent logic breaks at 2am, someone has to navigate `live_session` to find the 5 lines that matter.
- **`Cache-Control: no-store` regression is an operational trap**: The SKILL.md documents it as essential. The code removed it. When the next deploy causes stale-bundle complaints, there's no obvious signal pointing to the cache header — the symptom is "my changes aren't showing" and the fix requires knowing the history. At minimum, add a comment in `serve_index` explaining why the header is needed.

**Gaps:**
| Severity | Problem | Fix direction |
|---|---|---|
| Significant | `save_diagram` pattern diverges from every other endpoint — no auth, body-supplied token | Refactor to use `Depends(token_required)` and extract token from header |
| Significant | `live_session` is 340 lines inline in `main.py` — tool dispatch belongs in its own function | Extract tool dispatch logic into `app/handlers.py` or equivalent |
| Significant | `Cache-Control: no-store` removed without replacement — regression with no comment | Restore header and add an inline comment documenting why it must stay |

**Exit criteria:**
- [ ] `/api/diagram/{id}/save` has `Depends(token_required)` and no body-supplied token
- [ ] `id` removed from `ALLOWED_ATTRS` in `main.py:30`
- [ ] All `requirements.txt` deps pinned with `==`
- [ ] `Cache-Control: no-store` restored on `serve_index`
- [ ] `diagramContext` has an inactivity timeout to resume auto-gen
- [ ] `diagramMode` tool-call handling is explicit rather than blanket-drop

**Recommended fix order:**
1. **Auth bypass** — `/api/diagram/{id}/save` missing `token_required`. One-line fix, highest blast radius.
2. **Cache-Control regression** — Two lines restore. Prevents stale-bundle complaints after every deploy.
3. **`id` in `ALLOWED_ATTRS`** — One-line fix. Eliminates AI-content DOM injection.
4. **Pin dependencies** — `pip freeze > requirements.txt` while known-good.
5. **`diagramMode` tool swallowing** — Scope what gets dropped when in diagram mode and surface a user-facing message.
6. **`diagramContext` inactivity timeout** — Add a 30s `setTimeout` to clear `diagramContext` and resume auto-gen.
7. **`extra_components` cap** — Replace or cap at 5 entries to keep broadcast payloads bounded.
